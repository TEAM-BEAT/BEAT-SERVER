### 🎤 학생 여러분, 아직도 구글폼으로 공연 등록하세요? BEAT로 더 쉽고 빠르게!

![intro3](https://github.com/user-attachments/assets/7a0009a4-a73d-40fb-8976-2b1fa1d7d5f7)
![intro4](https://github.com/user-attachments/assets/7002609e-d4c6-45dd-9fd2-db1547929d1a)

학생 공연 단체들은 대부분 구글폼을 사용하여 공연을 등록하고 관리하고 있습니다. <br>
하지만 예매자의 입금여부를 직접 추적하고 다양한 문의사항을 개인 연락처를 통해 처리해야 하므로 번거로움과 부담을 느끼고 있죠 😭

BEAT는 이러한 문제를 해결하기 위해 탄생했습니다. <br>
**공연 등록, 관리, 예매, 조회까지 한 번에 할 수 있는 통합 플랫폼 BEAT**를 소개합니다! <br>
공연 단체들은 기존의 번거롭고 복잡한 구글폼 대신, BEAT를 사용하여 더 쉽고 편리하게 공연을 관리할 수 있습니다 😁

- **공연 등록**: 등록한 공연 정보를 수정 업데이트 할 수 있으며, 예매자 관리까지 한 곳에서 할 수 있습니다.
- **공연 관리**: 모든 공연 정보를 한 곳에서 관리하고 업데이트할 수 있습니다.
- **공연 예매**: 회원과 비회원 모두 쉽게 사용할 수 있는 예매 시스템으로 관객들이 편리하게 티켓을 구매할 수 있습니다.
- **공연 조회**: 실시간으로 내가 예매한 공연 내역을 조회할 수 있습니다.

BEAT와 함께 효율적이고 체계적으로 공연을 관리해 볼까요? 👏

## 🧩 Multi Module Architecture

BEAT-SERVER는 단일 모놀리스의 강결합을 해소하고, 역할과 변경 라이프사이클에 따라 **11개의 멀티 모듈**로 분리하여 설계되었습니다.

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ Apps (Composition Root & Inbound)                                           │
│ ┌───────────────────┐     ┌───────────────────┐     ┌─────────────────────┐ │
│ │     :apps:api     │     │    :apps:admin    │     │     :apps:batch     │ │
│ │ (User REST API)   │     │ (Admin REST API)  │     │ (Batch / Scheduler) │ │
│ └─────────┬─────────┘     └─────────┬─────────┘     └──────────┬──────────┘ │
└───────────┼─────────────────────────┼──────────────────────────┼────────────┘
            │                         │                          │
            ▼                         ▼                          ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ Application (Use Cases & CQRS Orchestration)                                │
│ ┌───────────────────┐     ┌───────────────────┐     ┌─────────────────────┐ │
│ │:application:      │     │:application:      │     │:application:        │ │
│ │ frontoffice       │     │ admin             │     │ system              │ │
│ └─────────┬─────────┘     └─────────┬─────────┘     └──────────┬──────────┘ │
└───────────┼─────────────────────────┼──────────────────────────┼────────────┘
            │                         │                          │
            ▼                         ▼                          ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ Domain (Pure Business Core · Zero Dependencies)                             │
│                                                                             │
│                                   :domain                                   │
│            Framework-Free Kotlin Aggregates & Business Rules                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
            ▲                         ▲                          ▲
            │                         │ (Implements Output Ports)│
┌───────────┴─────────────────────────┴──────────────────────────┴────────────┐
│ Infrastructure & Support (Outbound Adapters & Cross-Cutting)                │
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │                             :infrastructure                             │ │
│ │              Spring Data JPA · jOOQ CQRS · Redis · AWS S3               │ │
│ └─────────────────────────────────────────────────────────────────────────┘ │
│ ┌───────────────────────────────┐     ┌───────────────────────────────────┐ │
│ │     :support:security-web     │     │       :support:observability      │ │
│ │ (Spring Security / Filter)    │     │ (MDC Logging / OpenTelemetry)     │ │
│ └───────────────┬───────────────┘     └───────────────────────────────────┘ │
│                 │                                                           │
│                 ▼                                                           │
│ ┌───────────────────────────────┐                                           │
│ │       :support:security       │                                           │
│ │   (JWT / Password Crypto)     │                                           │
│ └───────────────────────────────┘                                           │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 💡 Multi Module 핵심 설계 원칙

1. **도메인 순수성 보장 (Zero-Framework)**
   - `domain` 모듈은 Spring, JPA 같은 외부 프레임워크나 라이브러리에 전혀 의존하지 않는 순수 Kotlin 코드로 작성했습니다.
   - 핵심 비즈니스 규칙과 상태 전이는 프레임워크 없이 오직 도메인 엔티티와 Aggregate Root가 안전하게 보호합니다.

2. **CQRS 기반 읽기/쓰기 분리 (JPA + jOOQ)**
   - **Command (상태 변경)**: `domain`의 Aggregate와 `Spring Data JPA`를 통해 비즈니스 불변식을 엄격히 검증하며 데이터를 저장합니다.
   - **Query (조회 최적화)**: 도메인 엔티티를 거치지 않고 `infrastructure`의 `jOOQ`를 통해 복잡한 조인과 페이징을 최적화된 SQL로 실행하여 N+1 없는 초저지연 조회를 제공합니다.

3. **독립적인 실행 런타임 (Composition Root)**
   - 하나의 거대한 서버 대신 사용자 API(`:apps:api`), 어드민 API(`:apps:admin`), 배치 스케줄러(`:apps:batch`)로 진입점을 분리했습니다.
   - 각 애플리케이션은 자신에게 필요한 유스케이스와 인프라 빈만 선택적으로 조립해 가볍고 빠른 부트스트랩과 독립 배포를 유지합니다.

4. **의존성 역전(DIP)과 ArchUnit 자동 검증**
   - 도메인과 유스케이스 계층이 필요한 Output Port를 인터페이스로 정의하고, 인프라 계층이 이를 구현하는 단방향 의존성을 철저히 지킵니다.
   - 모듈 간 의존성 방향과 패키지 격리 규칙은 CI 파이프라인에서 **ArchUnit**을 통해 자동으로 검증되어 아키텍처 부패를 원천 차단합니다.

### 📂 Directory Structure & Module Docs

```text
BEAT-SERVER
├── 📱 apps                    # 실행 애플리케이션 (Composition Root & HTTP 어댑터)
│   ├── api                    # 사용자 프론트오피스 REST API 서버
│   ├── admin                  # 관리자 백오피스 REST API 서버
│   └── batch                  # 정기 유지보수 및 배치 스케줄러 서버
├── 💼 application             # 유스케이스 및 트랜잭션 오케스트레이션 (CQRS)
│   ├── frontoffice            # 예매자 및 공연 메이커 비즈니스 유스케이스
│   ├── admin                  # 백오피스 프로모션/유저 관리 유스케이스
│   └── system                 # 취소 데이터 정리 및 만료 프로모션 유지보수 유스케이스
├── 🏛️ domain                  # 순수 비즈니스 도메인 모델 (Aggregate, 불변식, Port)
├── ⚙️ infrastructure          # 기술 구현 어댑터 (JPA, jOOQ CQRS 쿼리, Redis, AWS S3)
├── 🛡️ support                 # 횡단 관심사 기술 공통 모듈
│   ├── security               # Web 독립적 보안 프리미티브 (JWT, BCrypt, Security SPI)
│   ├── security-web           # Servlet Spring Security 필터 체인 및 인증 컨텍스트 연동
│   └── observability          # SLF4J MDC 로깅, OpenTelemetry 분산 트레이싱, Actuator
├── 🚀 ops                     # 인프라 & 배포 자동화 (Ansible, CloudFormation, Nginx)
└── 📚 docs                    # 아키텍처 정본(SSOT) 및 기술 설계 문서
```
